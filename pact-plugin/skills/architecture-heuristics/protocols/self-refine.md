# Protocol: self-refine (skill-specific part)

Context: this skill decays when a design review finds a new composition defect and nobody writes
down the question that would have caught it. Run this at the end of a session that used the skill.

Run the shared protocol [protocols/self-refine.md](../../../protocols/self-refine.md); its step 5 is the list below. Everything else (mission, log entry, validation, report) is shared.

## Skill-specific steps
- Review the session: which heuristic found something, which consumer or reader was missed, and
   which accepted decision later proved wrong.
- A new rule is a question a designer can ask of any change: one imperative line, no longer
   than its neighbours, in the matching reference.
- Keep project, employer and client names out. Distil the
   heuristic, not the incident.
- Do not add textbook patterns or generic anti-patterns; only ones a real incident used.

## Skill-specific guidelines
- Anti-pattern: turning a heuristic into a project checklist; the project doc owns that.
