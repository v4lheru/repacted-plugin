# Troubleshooting refusals: every rule id, what it refused and why, and the way through

A refused tool call ends in `<check>: <reason> → <instead> [rule: <id>]`: what was refused, what
to do instead, and the rule. The ids live in `hooks/shared/rules.py` (`RULES`, each with its
`instead`); `repact inspect --refusals` prints the sentence, the way through and the anchor on this page for
the last refusals of the session. One section per id; the anchor is the id with its dots and
underscores replaced by dashes.

```
repact inspect --refusals             # the last 5 refusals of this session: when, hook, rule, sentence, anchor
repact inspect --refusals last        # the most recent one
repact inspect --refusals <code>      # one refusal by the 12-hex code the refusal line showed
repact inspect --rule <id>            # one rule: its sentence, the way through and its anchor
```

The journal rows carry hashes, never the refused command or its reason text, so `repact inspect --refusals`
shows the id and its sentence, not what you typed. A refusal with no `[rule: ...]` tail is a plain
check verdict (`<check>.exit_2`): read the reason on the line; there is no fixed sentence or
`→ <instead>` for it.

The entries between the markers are generated by `bin/repact-docs-gen` from `hooks/shared/rules.py`; edit the registry, then run `python3 "bin/repact-docs-gen" --pages troubleshooting .` from the plugin root.

## Session and team state

## Process listings

<a id="process-listing"></a>
### `process.listing`

- **Rule:** A command would list processes with their full command lines (ps, pgrep -f, pstree, top -c, procs, htop, btop or a /proc argv file), so it was refused.
- **Why:** A listing that prints full command lines would also print any token passed as an argument to a running process, so only listings by pid and name are allowed.
- **Way through:** List processes by name only, with `pgrep -x <name>` or `ps -axo pid=,etime=,comm=`.

<a id="process-pty-wrap"></a>
### `process.pty_wrap`

- **Rule:** A command would run a KB step that only a human at a terminal may take (repact-distill promote, repact-distill team, vault-note drain/decide or kb-note drain/decide) inside a pseudo-terminal wrapper (script, expect, unbuffer, socat, a terminal multiplexer such as screen or tmux, or a pty spawn), so it was refused.
- **Why:** These steps check for a person at an interactive terminal, and a wrapper would fake one. The rule matches the command text, so it is a brake on habit, not a boundary: a wrapper started from a script file evades it, and so does a multiplexer driven across two separate commands, or a terminal from ssh -tt, asciinema rec -c, osascript's do script or an editor's terminal.
- **Way through:** Ask the user to run the step themselves in their own terminal; an agent may run `repact-distill promote --dry-run` to show what would be written.

## Credentials leaving the session

<a id="egress-url-credential"></a>
### `egress.url.credential`

- **Rule:** A git command named a remote URL whose user part carries a credential (a password, a variable such as `$TOKEN`, or a known token), so it was refused.
- **Why:** Git keeps a remote URL in .git/config and prints it with `git remote -v` and in errors, so a token inside it reaches the transcript in plain text. The rule reads the command as written: a URL held in a variable set earlier is not seen.
- **Way through:** Use the URL without the user:password part and let a credential helper supply the token (`gh auth setup-git`, or `git config credential.helper`).
